# Dataset Provenance

## Files

| File | Purpose | Tracked |
|---|---|---|
| `raw/SMSSpamCollection` | Official corpus, tab-separated `label<TAB>text` | Yes |
| `raw/readme` | The corpus's own readme, licence and disclaimer | Yes |
| `processed/train.csv` | 80 % of deduplicated rows | No (generated) |
| `processed/val.csv` | 10 % validation rows | No (generated) |
| `processed/test.csv` | 10 % held-out rows | No (generated) |

`processed/` is generated by `python scripts\prepare_data.py` and is intentionally
git-ignored: the raw file plus the fixed seed reproduces it byte for byte.

## Source

- **Corpus:** SMS Spam Collection v.1
- **Repository:** UCI Machine Learning Repository, dataset 228 ("SMS Spam Collection")
- **Download:** `https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip`
- **Authors:** Tiago A. Almeida, José María Gómez Hidalgo, Akebo Yamakami
- **Citation:** *Contributions to the Study of SMS Spam Filtering: New Collection and
  Results*, ACM DocEng 2011
- **Licence:** CC BY 4.0 as published by the UCI repository; the bundled `raw/readme`
  additionally requests citation and notification of use. See `THIRD_PARTY_NOTICES.md`.

## Column meanings

| Column | Meaning |
|---|---|
| `source_line` | 1-based line number in the raw file (set as the frame index before splitting) |
| `label` | `ham` or `spam`, exactly as published |
| `text` | Raw message text, unmodified |
| `dedupe_key` | Lower-cased, whitespace-collapsed, identifier-masked form used only for deduplication and leakage checks |

## Preparation decisions

1. **Exact normalised duplicates are removed before splitting.** The file contains
   5,574 rows but only 5,144 unique `dedupe_key` values; 430 duplicate rows were
   removed. This is the Amendment C requirement and is reported in
   `reports/conflict_report.json`.
2. **Conflicting labels are resolved by majority, ties dropped.** In this release
   the detected conflict-group count is **0** — no `dedupe_key` carried two
   different labels — so no row was relabelled or dropped for disagreement. The
   mechanism is still implemented and tested with synthetic data.
3. **Splitting is stratified and keyed on `dedupe_key`.** Because keys are unique
   before the split, each message appears in exactly one split.
4. **Nothing is labelled by hand.** Labels come only from the official file.

## Reproducing the splits

```cmd
python scripts\prepare_data.py
```

Observed output on the recorded run:

```text
raw_rows            5574
unique_dedupe_keys  5144
duplicates_removed   430
conflict_groups        0
train  rows=4115  ham=3613  spam=502
val    rows= 514  ham= 452  spam=62
test   rows= 515  ham= 452  spam=63
leakage: train__val=0 train__test=0 val__test=0
```

The `spam` counts in `val` and `test` differ by one (62 vs 63) because 10 % of the
spam class is not an integer; this is expected from stratified splitting, not a bug.
